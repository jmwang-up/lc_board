# 练习解题思路 Markdown 设计

## 1. 目标

为每次 LeetCode 练习单独保存一份可选的 Markdown 解题思路。用户可以在记录练习时填写和预览思路，也可以在题目历史中查看并单独编辑某次练习的思路，从而保留同一道题在不同时期的解法变化。

## 2. 范围

### 包含

- 每条练习记录保存独立的 Markdown 解题思路。
- 记录练习时提供“编辑 / 预览”标签切换。
- 题目历史渲染每次练习的 Markdown，并提供单独编辑入口。
- 编辑历史思路时只修改思路和更新时间，不修改日期或算法。
- 现有 IndexedDB 数据和旧版 JSON 备份兼容迁移。
- Markdown 安全渲染、字符上限、失败状态和自动化测试。

### 不包含

- 富文本或所见即所得编辑器。
- 完整代码编辑器、语法高亮主题或代码执行。
- 图片上传、附件、云端同步或多人协作。
- 在“编辑思路”弹窗中修改练习日期或算法。
- 题目级公共总结；思路只属于单次练习。

## 3. 数据模型与迁移

`Practice` 新增必有字段：

```ts
solutionMarkdown: string;
```

该字段在用户界面中选填，空字符串表示未记录思路。最大长度为 20,000 个 JavaScript 字符。

Dexie 数据库从版本 1 提升到版本 2。升级迁移遍历已有练习，为缺少该字段的记录写入空字符串。迁移不得改变题目、日期、主要算法、辅助算法或时间字段。

仓库接口新增：

```ts
updatePracticeSolution(practiceId: string, solutionMarkdown: string): Promise<Practice>;
```

该操作必须：

- 校验字符上限。
- 在同一个读写事务中确认练习仍存在。
- 只更新 `solutionMarkdown` 和 `updatedAt`。
- 练习不存在时抛出可识别的“练习已不存在”错误。

`recordPractice` 接受 `solutionMarkdown`，缺省值规范化为空字符串。

## 4. JSON 备份兼容

新版导出使用 `schemaVersion: 2`，并在每条 Practice 中包含 `solutionMarkdown`。

导入兼容两类备份：

- 版本 2 备份：校验 `solutionMarkdown` 是不超过 20,000 字符的字符串。
- 版本 1 备份：允许字段缺失，并在内存校验阶段规范化为空字符串，然后转成版本 2 内部模型。

备份解析、ID 重映射和 IndexedDB 写入仍遵守现有的“完整预检后单事务合并”规则。字段类型或长度不合法时，整个导入失败且本地数据不发生变化。

## 5. 记录练习体验

练习表单在算法选择区域后增加“解题思路（Markdown，可选）”。

编辑器采用两个标签：

- **编辑**：默认标签，显示多行文本框、当前字符数和 20,000 字上限。
- **预览**：渲染与历史详情一致的 Markdown。空内容显示“尚未填写解题思路”。

切换标签不修改或丢失输入内容。保存失败时，链接、题目信息、算法、日期和 Markdown 均保留，用户可以修正或重试。

超过字符上限时表单阻止保存，编辑区显示当前长度和明确错误。

## 6. 历史展示与单独编辑

题目历史中的每条练习在日期和算法标签后显示自己的解题思路：

- 非空内容直接渲染 Markdown。
- 空内容显示简短的“尚未记录解题思路”。
- 每条练习提供“编辑思路”按钮。

“编辑思路”打开独立模态框，复用相同的编辑/预览控件。该模态框只提交 Markdown 内容，不包含日期和算法控件。

保存成功后关闭模态框并刷新当前题目历史。取消关闭不执行写入。如果保存期间练习被其他标签页删除，模态框保持打开并显示“练习已不存在”。其他 IndexedDB 错误显示在模态框内部，输入内容保持不变。

模态框继续使用项目现有的焦点约束、背景 inert、Escape 关闭和焦点恢复模式。

## 7. Markdown 渲染与安全

使用一个共享的 `MarkdownContent` 展示组件，记录预览和历史详情必须复用该组件，避免渲染规则漂移。

支持：

- 标题、段落、强调、列表和引用。
- 表格。
- 链接。
- 行内代码和围栏代码块。

安全规则：

- 不解析或渲染原始 HTML。
- 不允许 `javascript:` 等危险协议生成可点击链接。
- 外部 HTTP/HTTPS 链接使用新标签页打开，并设置 `rel="noopener noreferrer"`。
- 代码块使用等宽字体和横向滚动，不执行内容。
- Markdown 渲染异常时显示错误提示，并保留可返回编辑模式的原始内容。

## 8. 组件边界

- `MarkdownEditor`：维护编辑/预览标签、文本输入、字符计数和本地校验；不直接访问仓库。
- `MarkdownContent`：唯一的安全 Markdown 渲染入口；不包含编辑或数据访问逻辑。
- `PracticeForm`：将 `solutionMarkdown` 纳入新练习表单和提交值。
- `EditPracticeSolutionDialog`：加载已有值、调用仓库更新、处理保存状态和错误。
- `ProblemDetails`：显示每次练习的思路并触发编辑入口。
- `DashboardRepository`：记录和更新练习思路，隐藏 Dexie 迁移及事务细节。

## 9. 错误处理

- 长度超过 20,000 时前端和仓库层都拒绝写入。
- Markdown 预览失败时显示渲染错误，不清空编辑内容。
- 更新不存在的练习时显示“练习已不存在”。
- IndexedDB 更新失败时保持模态框和输入内容，禁止重复提交直到本次请求结束。
- 导入的不合法 Markdown 使整个导入失败，不进行部分写入。
- 数据库迁移失败时由 Dexie 保持旧版本数据，应用显示现有数据加载错误状态。

## 10. 测试策略

### 数据层

- 新练习保存 Markdown 和空字符串默认值。
- 单独更新思路只改变 `solutionMarkdown` 与 `updatedAt`。
- 更新不存在的练习失败且不创建孤立数据。
- 20,000 字边界可保存，20,001 字被拒绝。
- 数据库迁移为旧练习补充空字符串且保留其他字段。
- 旧备份缺失字段可导入；新备份导出和恢复思路；非法类型或超长内容原子失败。

### 组件层

- 编辑/预览切换保持内容。
- Markdown 选填、字符计数和长度错误。
- 保存失败后输入不丢失。
- 历史记录分别展示不同练习的思路和空状态。
- 编辑保存、取消、缺失练习和 IndexedDB 错误。
- 原始 HTML 不执行，危险协议不生成可点击链接，外部链接具备安全属性。

### 端到端

1. 创建一条包含标题、列表和代码块的 Markdown 练习。
2. 在题目历史确认渲染结果。
3. 编辑该次练习的思路并刷新页面，确认新内容持久化。
4. 导出 JSON、清空数据、重新导入，确认 Markdown 内容恢复。

## 11. 完成标准

- 用户可以为每次练习选填最多 20,000 字符的 Markdown 解题思路。
- 记录时可以在编辑和安全预览之间切换。
- 历史记录按练习展示思路并允许单独编辑。
- 页面刷新和 JSON 导出/导入后思路仍正确存在。
- 现有 IndexedDB 数据和旧版备份无需人工处理即可继续使用。
- 相关数据层、组件和端到端测试通过。
