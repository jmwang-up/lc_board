# 从记录练习流程添加算法分类设计

## 1. 目标

用户在记录 LeetCode 练习时，如果需要的主要算法或辅助算法尚未创建，可以从记录表单直接进入数据管理页创建分类。创建完成后，应用自动返回原页面、重新打开记录弹窗、恢复全部草稿，并将新算法自动应用到发起入口。

## 2. 范围

### 2.1 包含

- 在“主要算法”和“辅助算法”区域分别提供“添加新算法”入口。
- 跳转到完整的数据管理页面，并自动聚焦算法创建表单。
- 创建成功后自动返回发起页面并恢复记录草稿。
- 根据入口将新算法设为主要算法或追加为辅助算法。
- 未创建算法时允许主动返回，并完整恢复草稿。
- 保留发起页面的完整路径和查询参数。

### 2.2 不包含

- 在记录弹窗中嵌套第二个创建算法弹窗。
- 把未完成的记录草稿写入 IndexedDB。
- 使用 `sessionStorage`、`localStorage` 或 URL 查询参数持久化草稿内容。
- 刷新浏览器后恢复未完成草稿。
- 改变算法重命名、替换或删除规则。

## 3. 状态与职责

`App` 统一管理一次临时的记录练习会话：

- 记录弹窗是否打开。
- 当前记录草稿。
- 添加算法目标：`primary` 或 `secondary`。
- 发起跳转前的完整位置，包括路径与查询参数。
- 返回后是否需要重新打开记录弹窗。

草稿包含当前表单的全部可编辑值：

- LeetCode 规范链接。
- 题号、中文题名和难度。
- 练习日期。
- 主要算法 ID。
- 辅助算法 ID 列表。
- Markdown 解题思路。

`RecordPracticeDialog` 负责查题、展示表单、保存练习和产生草稿快照，不直接导航到数据管理页。`PracticeForm` 负责把最新完整表单值交给弹窗，并通过两个带目标类型的回调发起添加算法。

`DataManagementPage` 和 `AlgorithmManager` 继续负责算法创建。添加流程中，它们额外接收创建成功回调和返回回调；普通进入数据管理页时这些回调不存在，行为保持不变。

## 4. 导航与数据流

### 4.1 发起添加

1. 用户在主要算法或辅助算法区域点击“添加新算法”。
2. `PracticeForm` 获取当前完整表单值，即使部分字段尚未通过最终提交校验也允许产生草稿。
3. `RecordPracticeDialog` 把草稿与目标类型交给 `App`。
4. `App` 保存当前完整位置，关闭记录弹窗并导航到 `/data?createAlgorithm=1`。

URL 只携带用于呈现添加模式的标记，不包含题目、日期、算法或 Markdown 草稿。

### 4.2 数据管理页

添加模式下：

- 页面显示“正在为本次练习添加主要算法”或“正在为本次练习添加辅助算法”。
- 算法名称输入框获得初始焦点。
- 页面保留完整的创建、重命名和删除能力。
- 页面显示“返回记录练习”按钮。

普通导航进入 `/data` 时，不显示添加模式提示或返回按钮。

### 4.3 创建成功

创建操作必须返回新建的 `Algorithm`，使上层获得确定的新算法 ID。创建成功后：

1. 数据管理页把新算法交给 `App`。
2. `App` 返回发起前的完整位置。
3. 记录弹窗重新打开并恢复草稿。
4. 目标为 `primary` 时，新算法 ID 替换草稿中的主要算法 ID。
5. 目标为 `secondary` 时，新算法 ID 追加到辅助算法列表。
6. 追加辅助算法时必须去重；如果新算法 ID 等于主要算法 ID，则不加入辅助算法。

数据管理页中的其他创建、重命名或删除操作不自动应用到草稿。只有本次创建表单成功返回的算法会触发自动返回。

### 4.4 未创建直接返回

点击“返回记录练习”时：

- 返回发起前的完整位置。
- 重新打开记录弹窗。
- 完整恢复草稿。
- 不修改主要或辅助算法选择。

## 5. 表单恢复与清理

恢复草稿时保留全部字段，包括查题或手动填写产生的元数据、算法选择和 Markdown。恢复不能触发现有的表单重置逻辑覆盖用户内容。

临时会话在以下时机清理：

- 恢复后成功保存练习。
- 恢复后用户主动关闭记录弹窗。
- 尚未进入添加流程时正常完成或取消记录。

仅在 React 内存中保存草稿。因此浏览器刷新、标签页关闭或应用重新加载后，未完成草稿自然失效。

## 6. 界面设计

算法选择区域包含两个上下文入口：

- “主要算法”下拉框旁的“＋ 添加新算法”。
- “辅助算法”标题旁的“＋ 添加新算法”。

即使算法列表为空，两个入口仍然可用。当前仅在算法列表为空时显示的单独数据管理跳转提示由统一入口替代，避免空列表与非空列表产生两套行为。

返回后，新算法必须立即出现在相应选择控件中。算法列表重新从仓库加载，不允许只把一个不存在于列表中的 ID 写入表单。

## 7. 错误与并发处理

- 算法名称为空、重复或仓库写入失败时，停留数据管理页并显示现有错误，不自动返回。
- 创建按钮在请求期间禁用，并使用同步提交保护避免快速重复创建。
- 如果加载算法列表失败，保留添加流程和返回入口；创建表单按现有错误策略展示失败。
- 返回记录弹窗后若草稿引用的旧算法已在数据管理页被删除，恢复时移除无效辅助算法；无效主要算法恢复为空并要求重新选择。
- 添加流程的完成回调只对当前临时会话有效。过期异步完成不得重开或修改新的记录会话。

## 8. 接口调整

仓库的 `createAlgorithm` 已返回 `Promise<Algorithm>`，无需改变持久化模型。

界面层新增的核心接口语义：

```ts
type AlgorithmTarget = 'primary' | 'secondary';

interface PracticeDraft {
  values: PracticeFormValues;
}

interface AddAlgorithmRequest {
  target: AlgorithmTarget;
  draft: PracticeDraft;
  returnLocation: string;
}
```

具体状态结构可以按现有 React 组件边界调整，但必须保持以下关系：

- 表单产生完整草稿。
- `App` 拥有跨路由临时会话。
- 数据管理页只报告创建成功的算法或主动返回。
- 记录弹窗负责恢复并重新加载算法列表。

## 9. 测试

### 9.1 组件测试

- 主要算法入口提交当前完整草稿和 `primary` 目标。
- 辅助算法入口提交当前完整草稿和 `secondary` 目标。
- 空算法列表仍显示两个添加入口。
- 数据管理添加模式自动聚焦算法名称输入框并显示上下文提示。
- 创建成功回传新算法；失败或重名时不回传。
- 未创建直接返回时不改变算法选择。
- 创建主要算法后返回并自动替换主要算法。
- 创建辅助算法后返回并自动追加且不重复。
- 新辅助算法与主要算法相同时不追加。
- 返回时保留链接、题目信息、日期、已有算法和 Markdown。
- 保存或主动关闭恢复后的弹窗会清理临时草稿。
- 普通数据管理入口不显示添加模式，也不会自动返回。

### 9.2 端到端测试

真实浏览器流程覆盖：

1. 打开记录练习并填写题目与 Markdown。
2. 从主要算法入口跳转数据管理页。
3. 创建新算法。
4. 自动返回原页面并重新打开记录弹窗。
5. 确认草稿完整且新算法已选为主要算法。
6. 保存练习并在历史中确认算法与思路均正确。

## 10. 验收标准

- 无论算法列表为空还是已有其他算法，记录表单都能发起上下文添加流程。
- 创建成功后自动返回原位置、恢复完整草稿并正确选中新算法。
- 未创建直接返回也能恢复草稿，且不改变算法选择。
- 失败、重名和重复提交不会错误返回或产生重复算法。
- 普通数据管理行为、现有练习保存和算法删除规则不回归。
- 草稿不进入持久化存储或 URL，刷新后不承诺恢复。
