# LeetCode 个人刷题看板设计

## 1. 目标

构建一个本地优先的个人 LeetCode 刷题看板。用户每天记录完成的题目以及采用的主要算法和辅助算法，并能在一段时间后按题目、算法或日期回看历史解法。

第一版面向单个用户，不需要登录或云端同步。数据保存在浏览器本地，同时提供 JSON 导入导出，且架构允许未来部署为在线 Web 应用。

## 2. 第一版范围

### 包含

- 支持 `leetcode.cn` 题目链接。
- 根据链接自动查询题号、中文题名和难度。
- 查询失败时允许手动填写题目信息。
- 保存题目主记录，并为同一道题保存多次独立练习。
- 每次练习选择一个主要算法和零到多个辅助算法。
- 算法分类完全由用户创建，不提供固定预设。
- 首页以算法分类为核心，并展示最近练习和刷题活跃日历。
- 支持按题号、题名、主要/辅助算法、难度和练习日期搜索或筛选。
- 支持 JSON 备份的导出与合并导入。

### 不包含

- LeetCode 账号登录或提交记录同步。
- `leetcode.com` 国际站支持。
- 解题思路、代码、复杂度、错题原因和复习计划。
- 多用户、登录、云同步和跨设备实时同步。
- 桌面应用打包。

## 3. 技术方案

采用 React、TypeScript 和 Vite 构建单页应用，使用 IndexedDB 保存个人数据，使用轻量 Node 服务作为 LeetCode 元数据代理。

选择该方案的原因：

- 本地开发和启动简单，适合个人工具第一版。
- 个人数据不经过服务端，隐私边界清晰。
- IndexedDB 足以支持结构化数据、索引和离线持久化。
- 元数据代理绕开浏览器跨域限制，并隔离 LeetCode 查询协议变化。
- 未来可以部署静态前端和轻量 API，也可以替换持久层而不重写页面。

## 4. 系统架构

系统分为三个独立单元：

1. **Web 前端**：负责页面、表单、搜索筛选、统计、日历和导入导出。
2. **本地数据仓库**：封装 IndexedDB，负责题目、练习和算法分类的事务性读写。
3. **元数据代理**：校验 `leetcode.cn` 链接中的题目 slug，查询公开题目信息并返回统一结果；不保存用户刷题数据。

正常数据流：

1. 用户粘贴 `leetcode.cn/problems/<slug>/` 链接。
2. 前端解析并将 slug 发送给元数据代理。
3. 代理向 LeetCode 查询题号、中文题名和难度。
4. 用户选择主要算法、辅助算法和练习日期。
5. 前端在一个本地事务中创建或复用题目，并新增练习记录。
6. 首页统计和筛选结果从 IndexedDB 重新计算或查询。

如果元数据查询失败，流程在第 3 步降级为手动填写，不阻断保存。

## 5. 页面与交互

### 5.1 全局导航

主导航包含“算法看板”“题目记录”“数据管理”，并始终提供“记录练习”主操作按钮。

### 5.2 算法看板

首页以用户创建的算法分类为主要信息层级。每张分类卡片展示关联题目数和练习次数。首页同时展示最近练习记录和按日期汇总的刷题活跃日历。

点击分类卡片进入已经应用该算法筛选条件的题目记录页。主要算法和辅助算法均可被筛选，但首页归类和主要统计以主要算法为准。

### 5.3 题目记录

题目记录页提供：

- 按题号或题名搜索。
- 按主要算法、辅助算法、难度和日期范围筛选。
- 题目列表及最近练习摘要。
- 题目详情，展示该题的所有练习，并按日期倒序排列。

### 5.4 记录练习

记录流程使用弹窗，分三步完成：

1. 粘贴链接并自动补全题目信息；失败时手动填写。
2. 选择或新建一个主要算法，并可选择多个辅助算法。
3. 选择练习日期，默认为当前本地日期，然后保存。

题目已存在时只新增练习；题目不存在时先建立题目，再新增练习。允许同一天对同一道题保存多次练习。

### 5.5 数据管理

数据管理页用于：

- 创建、重命名和删除算法分类。
- 导出完整 JSON 备份。
- 导入并校验 JSON 备份。
- 在危险操作区清空全部本地数据；操作前显示数据数量并要求二次确认。

删除正在使用的算法分类时，默认要求选择一个替代分类。只有用户明确选择删除相关练习并二次确认后，才允许级联删除。

## 6. 数据模型

### Problem

- `id`: 应用生成的稳定唯一 ID。
- `leetcodeSlug`: 从 URL 提取的 slug，全局唯一。
- `frontendQuestionId`: LeetCode 展示题号。
- `titleZh`: 中文题名。
- `difficulty`: `easy | medium | hard`。
- `url`: 规范化后的 `leetcode.cn` URL。
- `createdAt`: 创建时间。

### Practice

- `id`: 应用生成的稳定唯一 ID。
- `problemId`: 关联 Problem。
- `practicedOn`: 用户本地时区的 `YYYY-MM-DD` 日期。
- `primaryAlgorithmId`: 一个必填 Algorithm。
- `secondaryAlgorithmIds`: 零到多个 Algorithm ID，不得包含主要算法且不得重复。
- `createdAt`: 创建时间。
- `updatedAt`: 更新时间。

### Algorithm

- `id`: 应用生成的稳定唯一 ID。
- `name`: 去除首尾空格后唯一，比较时不区分大小写。
- `color`: 用于看板识别的展示颜色。
- `createdAt`: 创建时间。

### 关系和约束

- 一个 Problem 对应多条 Practice。
- 一条 Practice 必须有且仅有一个主要 Algorithm，可有多个辅助 Algorithm。
- 相同 `leetcodeSlug` 不得创建重复 Problem。
- 删除 Problem 将删除其 Practice，但必须二次确认。
- 删除 Practice 不删除 Problem；没有练习的 Problem 可以保留或手动删除。

## 7. 元数据代理契约

前端只向代理提交已解析的 slug，不允许代理请求任意 URL，以避免开放代理和服务端请求伪造风险。

请求示例：

```http
GET /api/leetcode/problems/two-sum
```

成功响应包含：

```json
{
  "slug": "two-sum",
  "frontendQuestionId": "1",
  "titleZh": "两数之和",
  "difficulty": "easy",
  "url": "https://leetcode.cn/problems/two-sum/"
}
```

错误响应使用统一错误码，例如 `INVALID_SLUG`、`NOT_FOUND`、`UPSTREAM_TIMEOUT` 和 `UPSTREAM_CHANGED`。代理设置短超时，不记录查询之外的用户数据。

## 8. JSON 备份

导出文件包含 `schemaVersion`、`exportedAt`、`problems`、`practices` 和 `algorithms`。

导入分为两个阶段：

1. 在内存中验证 JSON 结构、版本、字段类型、唯一约束和所有引用关系。
2. 验证成功后在单个 IndexedDB 事务中合并数据。

第一版只提供“合并导入”。相同 ID 的本地记录优先，导入记录被跳过并在结果摘要中报告。不同 ID 但 `leetcodeSlug` 相同的 Problem 视为同一题，导入的 Practice 重新关联到本地 Problem。算法名称冲突按不区分大小写的规范化名称合并，并重新映射练习引用。任何无法安全重映射的冲突都会使整个导入失败，避免部分写入。

## 9. 错误处理

- 非 `leetcode.cn/problems/<slug>/` 链接在前端直接拒绝。
- 元数据查询超时、限流或响应格式变化时显示具体错误，并开放手动填写。
- IndexedDB 写入失败时保留表单内容，允许重试。
- 导入校验失败时不写入任何数据，并显示可定位到字段或记录的错误。
- 破坏性操作需要二次确认，并明确受影响的题目或练习数量。
- 清空全部数据必须输入指定确认词；清空在单个事务中完成，失败时整体回滚。
- 空数据、无搜索结果和首次使用均提供明确引导，不显示失效控件。

## 10. 测试策略

### 单元测试

- LeetCode URL 与 slug 解析和规范化。
- 统计、搜索和组合筛选。
- 数据模型约束。
- JSON schema 校验、冲突检测和 ID 重映射。

### 组件测试

- 添加练习及手动降级表单。
- 主要和辅助算法选择约束。
- 搜索筛选器、题目详情和删除确认。
- 导入预检与结果摘要。

### 端到端测试

- 首次创建算法并记录新题。
- 再次练习已有题目并使用不同算法。
- 从算法分类、搜索和日历回查历史。
- 导出、清空和导入后恢复完整数据。

元数据代理测试使用固定模拟响应，不依赖真实 LeetCode 服务。仅保留一个可选的手动集成检查验证当前上游协议。

## 11. 完成标准

第一版完成需满足：

- 用户可以通过 `leetcode.cn` 链接或手动输入记录题目。
- 同一道题可保存并展示多次练习和不同算法。
- 三种回查方式均可使用：题号/题名、算法/难度、练习日期。
- 刷新或关闭浏览器后数据仍然存在。
- LeetCode 查询不可用时不影响手动记录和历史浏览。
- JSON 能完成一次可靠的导出、清空、导入恢复。
- 核心单元、组件和端到端测试通过。

## 12. 后续扩展方向

未来可以在不改变第一版核心模型的前提下增加国际站、解题笔记与代码、复习计划、云数据库、登录和跨设备同步。这些能力不进入本次实现范围。
